# 順次接続試行シーケンス図

```plantuml
@startuml
box "アプリ (MainActivity)" #LightGreen
    participant "measureAllSupplicant\n〔measureAll() と measureForAp()〕" as App
    participant "BroadcastReceiver\n〔受け皿①Supplicant状態〕" as Recv
    participant "NetworkCallback(cb)\n〔受け皿②接続成否〕" as Cb
end box

box "Android OS" #LightBlue
    participant "ConnectivityManager" as OS
    participant "wpa_supplicant" as Sup
end box

== 停止ボタン押下時（任意のタイミングで割り込み可） ==
note over App : stopRequested = true
App -> App : supplicantContinuation.resume()\n（Phase1/Phase2待機中なら即時起こす）
App -> App : continuation = null\nunregisterNetworkCallback()
note over App : 次APループ先頭で\nstopRequested チェック → CANCELLED

== 通常フロー ==

loop AP1件ごと（全AP分繰り返し）

    App -> App : buildSpecifier()\nBSSID+SSID+セキュリティでリクエスト構築
    note over App : WEP → SKIPPED で即終了\n（WifiNetworkSpecifierがWEP非対応のため）\n構築失敗（BSSIDが不正等）→ SKIPPED で即終了

    App -> App : supplicantContinuation セット\n（止まったコルーチンへの再開ボタンをフィールドに保存）
    App -> OS : requestNetwork(request, cb)
    note over App : ここでsuspendCancellableCoroutineにより\nコルーチンを一時停止。\ncb内でcont.resume()が呼ばれるまで\nこの行で待ち続ける。
    OS -> Sup : 接続試行指示

    note over App : ── Phase1待機（最大15秒）\nOSが動き出したかを確認──

    alt ① BroadcastReceiverにSupplicant状態が来る
        Sup --> Recv : SUPPLICANT_STATE_CHANGED_ACTION
        Recv -> App : 最初の状態受信 → continuation.resume()
        note over App : Phase1 完了\n→ Phase2へ進む\n（wpa_supplicantが動き出した確認のみ。\n認証成否はまだ不明）
    else ② OSが接続不可と判断
        OS --> Cb : onUnavailable()
        Cb -> App : unavailableFired = true\ncontinuation.resume()
        note over App : Phase1 完了\n→ Phase2スキップ・NOT_FOUND・次のAPへ
    else ③ OSが接続成功を通知
        OS --> Cb : onAvailable(network)
        Cb -> App : finalState = COMPLETED\ncontinuation.resume()
        note over App : Phase1 完了\n→ Phase2スキップ・結果確定・次のAPへ
    else ④ 15秒どれも来ない
        note over App : FAILED_AT_DIALOG_TIMEOUT\n→ Phase2スキップ・結果確定・次のAPへ
    end

    note over App : ［①のみここへ到達］\n── Phase2待機（最大8秒）\n接続試行の結果を確認＆状態遷移を記録──

    loop Supplicant状態が届くたびに（Phase2）
        Sup --> Recv : SUPPLICANT_STATE_CHANGED_ACTION
        Recv -> App : 状態を supplicantTransitions に追記
        alt COMPLETED
            Recv -> App : continuation.resume()
            note over App : finalState = COMPLETED\n→ continuation.resume()でループを抜ける\n↓ 後片付けへ
        else DISCONNECTED（ASSOCIATED等を経由）
            Recv -> App : continuation.resume()
            note over App : finalState = FAILED_AT_DISCONNECTED\n→ continuation.resume()でループを抜ける\n↓ 後片付けへ
        else その他の状態
            note over Recv : resumeしない → ループ継続\n（次のSupplicant状態を待つ）
        end
    end

    note over App : 8秒タイムアウトの場合も\nwithTimeoutOrNullがループを強制終了\nfinalState = TIMEOUT_AT_最終状態\n↓ 後片付けへ

    note over App : ── 後片付け（全分岐がここに合流）──
    App -> App : unregisterNetworkCallback()
    App -> App : supplicantStates + finalState を確定・記録
    App -> App : delay(300ms)

end

App -> App : 全AP分の結果リストを返却
@enduml
```

## 補足

| フェーズ | 最大待機時間 | 早期終了条件 |
|---------|------------|------------|
| Phase1  | 15秒 (DIALOG_TIMEOUT_MS) | 最初のSupplicant状態受信 / onUnavailable() |
| Phase2  | 8秒 (AUTH_TIMEOUT_MS) | COMPLETED / DISCONNECTED(+ASSOCIATED等) |
| AP間    | 300ms固定 | なし |

## アプリが能動的に行っていること

- `requestNetwork()` の呼び出し（接続試行のトリガー）
- タイムアウト管理
- Supplicant状態の記録

## OSが行っていること（アプリ干渉不可）

- ダイアログ表示・非表示の判断
- 実際のWiFiフレーム送受信・認証処理
- `SUPPLICANT_STATE_CHANGED_ACTION` の発火タイミング
- `onAvailable()` / `onUnavailable()` の呼び出し
