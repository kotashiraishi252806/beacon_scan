# 先行研究 サプリカント取得アプリ 調査結果

## 対象アプリ
- 端末: ASUS_I006D (Zenfone 8)
- 測定日: 2026-09-30

---

## サプリカント状態取得に使用しているメソッド

- `WifiManager.connectionInfo` — 接続中 Wi-Fi の `WifiInfo` オブジェクト取得
- `WifiInfo.supplicantState` — サプリカント状態の取得
- `WifiManager.NETWORK_STATE_CHANGED_ACTION` のブロードキャストレシーバ — Wi-Fi 状態変化の検知
- `NetworkInfo.detailedState` — 詳細接続状態の取得

## サーバへの送信機能

なし。データはローカルの CSV ファイルへの書き込みのみ。

---

## 測定開始から終了までのユーザ操作およびアプリ内処理

| 時系列 | ユーザ操作 | アプリ内処理 |
|---|---|---|
| 1 | アプリ起動 | 位置情報・Wi-Fi 権限のパーミッション確認 |
| 2 | Button を押す | `isRunning=true`、ファイル名生成（日付＋機種名）、`WifiScan` のブロードキャストレシーバ2つ登録、`RssiMeasurement` 開始 |
| 3 | 待機 | `NETWORK_STATE_CHANGED_ACTION` 受信 → `onWifiStateChange` 発火 → `WifiInfo` 収集コルーチン開始、`startWifiScan()` 実行 |
| 4 | 待機（移動） | `SCAN_RESULTS_AVAILABLE_ACTION` 受信 → 周辺 AP スキャン結果取得・GPS 座標取得・バッファに追加（500ms ループ） |
| 5 | 待機（移動） | `supplicantState` または `detailedState` が前回から変化した場合のみ `WifiState.csv` に1行書き込み |
| 6 | 待機（移動） | バッファが50件に達したら `WifiBeacon.csv` に書き込み・バッファクリア |
| 7 | Button を再度押す | `isRunning=false`、ブロードキャストレシーバ2つ解除、`RssiMeasurement` 停止、残バッファを `WifiBeacon.csv` に書き込み |
| 8 | 自動 | 両 CSV ファイルを端末の Documents フォルダにコピー |

## 取得されるデータ構造

### WifiState.csv（Wi-Fi 接続状態ログ）

| カラム名 | 内容 |
|---|---|
| dateTime | 記録日時 |
| latitude / longitude | GPS 座標 |
| supplicantState | サプリカント状態 |
| detailedState | 詳細接続状態 |
| currentSecurityType | セキュリティ種別 |
| ssid / bssid | 接続先 AP 情報 |
| frequency | 周波数 (MHz) |
| networkId | ネットワーク ID |
| wifiStandard | Wi-Fi 規格 |
| rssi | 受信信号強度 (dBm) |
| rxLinkSpeedMbps / txLinkSpeedMbps | 送受信リンクスピード |
| linkSpeed | リンクスピード |
| ipAddress | IP アドレス |
| isRestricted | Wi-Fi 制限フラグ |
| uuid | 端末識別子（機種名） |

### WifiBeacon.csv（周辺 AP ビーコンスキャンログ）

| カラム名 | 内容 |
|---|---|
| date | 記録日時 |
| latitude / longitude | GPS 座標 |
| ssid / mac | AP の SSID と BSSID |
| rssi | 受信信号強度 (dBm) |
| capabilities | セキュリティ方式 |
| frequency | 周波数 (MHz) |

## スキャンと接続試行について

- `wifiManager.startScan()` によるビーコンスキャンは実装・実行されている
- `WifiConnector.connectToWifi()` は Android の Wi-Fi 設定画面を開く処理のみであり、802.11 のフレーム交換を直接トリガーするメソッド呼び出しではない
- `WifiConnector` のインスタンスは生成されているが、`connectToWifi()` はコード中のいかなる箇所からも呼び出されていない
- `SupplicantState` の遷移を発生させる（802.11 認証・アソシエーション・4-way handshake のフレーム交換を開始させる）明示的なメソッド呼び出しはコードから確認できない
- アプリは `NETWORK_STATE_CHANGED_ACTION` ブロードキャストで状態変化を受動的に監視・記録している
