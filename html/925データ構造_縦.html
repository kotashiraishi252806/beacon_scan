beacon_scan — サプリカント測定データ構造

このドキュメントは、beacon_scan アプリのサプリカント状態取得機能が生成するセッションの JSON データ構造を第三者向けに解説します。（2025-09 版）

① データ構造の全体像

1回のスキャンが 1エントリ を生成します。 エントリは端末内ファイル pending_scans.json（配列）に蓄積され、 HTTP POST でサーバへ送信されます。

② スキャン単位のフィールド
フィールド名型説明
scan_id string スキャン1回ごとに生成するUUID。常に取得
device_id string 端末を識別するUUID。初回起動時に生成し SharedPreferences に永続保持。常に取得
device.manufacturer string 端末メーカー名（例: "samsung"）。常に取得
device.model string 端末モデル名（例: "Pixel 8"）。常に取得
device.android_api int Android APIレベル（例: 34 = Android 14）。常に取得
scanned_at string スキャン実行時刻（ISO 8601形式）。常に取得
label string 自動スキャンのセッション単位ラベル（例: "2025/09/25 14:00〜14:30"）。手動スキャン・未設定時は空文字。
location.latitude double GPS位置情報。取得できない場合は location ごと null。null あり
location.longitude double
location.accuracy_m double
③ AP 単位のフィールド（access_points 配列の各要素）

1スキャンで検出された AP の数だけ要素が存在します。同一 BSSID の複数スキャン結果は最強 RSSI の1件に集約されます。

フィールド名型説明
bssid string AP の MACアドレス（XX:XX:XX:XX:XX:XX 形式）。APを識別する主キー。常に取得
mld_mac_address string? Wi-Fi 7 MLO（Multi-Link Operation）対応 AP の物理 MACアドレス。API 33未満またはMLO非対応APでは null。null ありAPI 33+
oui string BSSID の先頭3オクテット（ベンダー識別子）。例: "aa:bb:cc"。BSSID から常に導出可能。常に取得
ssids string[] この BSSID が発している SSID の一覧。非公開 AP では空配列 []。常に取得
rssi_dbm int 電波強度（dBm）。値が大きいほど強い（例: -55 > -80）。常に取得
frequency_mhz int 使用周波数（MHz）。例: 2437, 5180, 6115。常に取得
band string frequency_mhz から導出した帯域。値: "2.4GHz" / "5GHz" / "6GHz"。常に取得
channel_width_mhz int チャネル幅。値: 20 / 40 / 80 / 160 / 320 (MHz)。常に取得
wifi_standard string Wi-Fi 世代の文字列。値: "802.11a/b/g" / "802.11n" / "802.11ac" / "802.11ax" / "802.11be"。常に取得
wifi_standard_code int Wi-Fi 世代の整数コード（ScanResult.wifiStandard の値）。wifi_standard と対応。常に取得
security string セキュリティ規格。値: "Open" / "WEP" / "WPA" / "WPA2" / "WPA3" / "WPA2/WPA3"。API 33+ は securityTypes、以前は capabilities 文字列を解析して判定。常に取得
capabilities_raw string OS が組み立てたセキュリティ情報の生文字列。例: "[WPA2-PSK-CCMP][RSN-PSK+SAE-CCMP][ESS]"。端末・APドライバにより表現が異なる場合あり。常に取得
④ サプリカント測定フィールド（AP 単位）

スキャン後に「AP を選択して測定」した場合に付与されます。 測定前は supplicant_final_state = "NOT_MEASURED" で、このフィールド群はデフォルト値のまま送信されます。

フィールド名型説明
supplicant_states string[] 接続試行中に wpa_supplicant が発した状態遷移の時系列リスト（順番保持）。
例（Open AP）: ["DISCONNECTED", "SCANNING", "AUTHENTICATING", "ASSOCIATING", "ASSOCIATED", "COMPLETED"]
例（WPA2・パスワード不一致）: ["DISCONNECTED", "ASSOCIATING", "ASSOCIATED", "FOUR_WAY_HANDSHAKE", "DISCONNECTED"]
supplicant_final_state string 接続試行の結末を表す文字列。値の詳細は下の凡例を参照。
supplicant_elapsed_ms long AP 1台あたりの接続試行にかかった時間（ミリ秒）。測定未実施時は -1。最大 10,000ms（タイムアウト値）。
⑤ supplicant_final_state — 値の凡例
COMPLETED 接続が最後まで成立（onAvailable または SupplicantState.COMPLETED 到達）。Open AP では通常この値。
FAILED_AT_<STATE> 接続が途中で失敗し、最終サプリカント状態が DISCONNECTED / INACTIVE / SCANNING のいずれかで終了。
例: FAILED_AT_DISCONNECTED（WPA2 でハンドシェイク失敗後に切断）
TIMEOUT_AT_<STATE> 10秒タイムアウト到達時点の最終状態名が付く。状態遷移は起きたが完了・失敗に至らなかった場合。
例: TIMEOUT_AT_ASSOCIATING
NOT_FOUND onUnavailable が発火し、かつ状態遷移が 0 件だった場合。AP が圏外になったか、OS が接続要求を即座に拒否した。
FAILED_AT_DIALOG_TIMEOUT タイムアウト到達時点でサプリカント遷移が 0 件（onUnavailable も来なかった）。接続試行が OS に受け付けられなかった可能性。
SKIPPED WEP AP は測定対象外のためスキップ。接続試行は行わない。
CANCELLED ユーザが「測定中断」ボタンを押した後の残り AP に付与。
NOT_MEASURED サプリカント測定を実施していないデフォルト値。
⑥ 1スキャンセッションの流れ
①スキャンボタン押下 → GPS 取得 → wifiManager.startScan()
↓
②OS から SCAN_RESULTS_AVAILABLE_ACTION 受信 → AP リストを BSSID 単位に集約（同一 BSSID は最強 RSSI の1件に）
↓
③ユーザが AP を選択して「測定」ボタン → SupplicantMeasurer.measureAll() 開始
↓
④AP 1 台ずつ順番に requestNetwork() → サプリカント状態遷移を記録 → 最大 10 秒待機（無応答 3 秒で早期終了）
↓
⑤全 AP 完了 → saveToPending() で pending_scans.json に追記
↓
⑥送信モードON の場合 → HTTP POST でサーバへ送信 → 成功したエントリをファイルから削除
