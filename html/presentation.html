SUPPLICANT FINAL STATES

supplicant_final_state — 理論上 18種類

コードの判定ロジックから導出。4グループに分類。実測済 8種 ／ 未観測（理論値）10種。

① 成功（1種）
COMPLETED onAvailable() 受信 — Layer 2 接続確立
② 測定対象外・中断（4種）— supplicant 遷移なし
SKIPPED WEP 等、specifier 組み立て不可
CANCELLED 停止ボタン押下（未測定 AP をスキップ）
NOT_FOUND onUnavailable() かつ supplicant 遷移 0件
FAILED_AT_DIALOG_TIMEOUT 15秒タイムアウト かつ 遷移 0件 かつ onUnavailable なし
③ 明示的失敗 FAILED_AT_*（3種）— last state が切断系
last state が DISCONNECTED / INACTIVE / SCANNING のとき
FAILED_AT_DISCONNECTED 認証失敗・AP 側から切断（最多）
FAILED_AT_INACTIVE supplicant が非活性状態で終了
FAILED_AT_SCANNING AP 探索フェーズで終了（電波弱等）
④ タイムアウト TIMEOUT_AT_*（10種）— last state がそれ以外
15秒経過時に接続が完了していない状態 or COMPLETED 到達でも onAvailable 未受信の場合、 そのとき最後に受信した SupplicantState の名前を suffix に付ける
最終状態対応する SupplicantState補足
TIMEOUT_AT_INTERFACE_DISABLED INTERFACE_DISABLED WiFi 切替中に停止
TIMEOUT_AT_AUTHENTICATING AUTHENTICATING 認証フレーム送出中に停止
TIMEOUT_AT_ASSOCIATING ASSOCIATING Association 処理中に停止
TIMEOUT_AT_ASSOCIATED ASSOCIATED L2 接続完了後、鍵交換前に停止
TIMEOUT_AT_FOUR_WAY_HANDSHAKE FOUR_WAY_HANDSHAKE WPA 鍵交換中に停止
TIMEOUT_AT_GROUP_HANDSHAKE GROUP_HANDSHAKE グループ鍵交換中に停止
TIMEOUT_AT_COMPLETED COMPLETED L2 確立済みだが onAvailable 未受信 ⚠
TIMEOUT_AT_DORMANT DORMANT 休眠状態（理論値・未観測）
TIMEOUT_AT_UNINITIALIZED UNINITIALIZED 未初期化（理論値・未観測）
TIMEOUT_AT_INVALID INVALID 不正状態（理論値・未観測）
SupplicantState enum（Android API 30）の全 13値 から DISCONNECTED / INACTIVE / SCANNING の 3値を除いた残り 10値が対応

注目事項：WPA2/WPA3 混在モード AP での異常挙動

ダミーパスワードなのに COMPLETED（Layer 2 接続確立）に到達するケースを 3件確認

何が起きているか（仮説）

  • WPA2/WPA3 混在モード（Transition Mode） の AP は [RSN-PSK+SAE-CCMP] を capabilities に持ち、 WPA2 と WPA3 の両方で接続を受け付ける
  • ダミー PW で WPA3/SAE として接続試行した際、AP 側が WPA2-PSK にフォールバックしてしまい、 4-way ハンドシェイクが通過してしまった可能性
  • 同 SSID の WPA3 専用 AP（ec:5a:31:9d:5e:93）では 通常通り FAILED_AT_DISCONNECTED になっており、 混在モード特有の挙動と考えられる
  • eduroam での TIMEOUT_AT_COMPLETED は Fast Transition（FT）有効の EAP AP 特有の動作の可能性

今後の調査方針

  • 同 AP に対して WPA2 専用の指定（非 SAE）で接続試行した場合の挙動を確認
  • capabilities_raw の詳細解析で Transition Mode の条件を特定
  • 実際にアクセスポイントの設定を確認し、混在モードか検証
  • 別端末・別 OS バージョンで同 AP を測定して再現性を確認
  • セキュリティ分類ロジックの改善（PSK+SAE を別カテゴリで処理）
ダミーPWでCOMPLETEDに到達するということは、 実際にはネットワークへの不正なアクセスが可能な状態になっている可能性もあり、 セキュリティ上の観点からも調査価値が高い。
