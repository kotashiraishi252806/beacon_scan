取得機能を実装
事実： 先行研究のサプリカント取得（wifiManager.connectionInfo.supplicantState）は 接続中の 1 台のみを対象とする。同一 SSID が複数の AP に設定されている環境では、 全 AP を測定できない。
考察： 同一 SSID が設定されている各 AP を網羅的に測定できたほうが、 その無線LAN環境をより有意義に把握できる。 全 AP を測定するには、アプリ側から能動的に接続試行を行う手段が必要。
提案： WifiNetworkSpecifier + requestNetwork() を用いて、 スキャンで検出した全 AP に対して順番に接続試行を行い、 サプリカント状態遷移を記録する。 また、全 AP 対応のデータ構造を新たに定義し、スキャン結果を JSON 形式でサーバーへ送信する。
接続試行の定義

「接続試行」とは何か

採択した定義： 特定の AP を指定して ConnectivityManager.requestNetwork() を呼び出すこと。

補足： 採択した定義の ConnectivityManager.requestNetwork() は、 アプリが Android OS に対して「この AP への接続を開始してほしい」と依頼する API コールである。 上記の図を行うために、OS に指示を出すメソッド。 アプリからは requestNetwork() 呼び出し後に OS が実際にどのフレーム交換を行ったかを直接観測することはできない。 そのため、実装上の接続試行を requestNetwork() の呼び出しと定義している。
