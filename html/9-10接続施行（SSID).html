接続施行測定（SSID）
実装要件定義

SsidMeasurementActivity — セッション型・複数地点測定フロー
1 概要と目的

接続施行測定（SSID）は、ユーザが選択したSSIDを持つBSSID（AP）に対して順次接続試行（Supplicant測定）を行い、複数地点を移動しながら繰り返し測定するためのアクティビティである。

接続施行測定（AP）との主な違いは、

  • リスト表示単位が BSSID（物理AP） ではなく SSID（論理ネットワーク）
  • 測定がワンショットではなく セッション型の繰り返し になること

内部データ構造・送信スキーマはAP版と同一。測定対象はBSSIDのまま。

2 セッション構造
定義
  • セッション = 複数地点にわたる一連の測定をまとめた1単位
  • セッション開始時刻〜終了時刻の範囲で label を生成（AP版の自動スキャンと同方式）
  • セッション中のすべてのスキャンエントリは同一の session_uuid をlabelとして保持し、セッション終了時にタイムスタンプ文字列（例: 2026/09/10 13:00~13:45）へ一括更新する
  • 選択SSIDはセッション開始時に確定し、セッション終了まで固定
3 測定フロー（1セッション）
  • スキャン実行
    ユーザ操作スキャンボタンを押す。SSIDグループ単位でリスト表示。
  • 測定対象SSIDを選択
    ユーザ操作チェックボックスで測定したいSSIDを選択。「セッション開始」ボタンが有効化される。
  • セッション開始
    ユーザ操作「セッション開始」ボタンをタップ（確認ダイアログなし）。選択SSIDが固定され、セッション開始時刻を記録。選択SSIDの全BSSIDへの接続試行を即座に開始。
  • BSSID単位で順次接続試行
    自動選択SSIDに紐づく全BSSIDへ順次Supplicant測定。
    OS制御接続確認ダイアログはAndroid OSが制御。ユーザはダイアログ応答のみ担当。
  • 測定完了 → 移動待ち表示
    自動「次の測定場所に移動してください」を画面表示。「移動完了・測定開始」「セッション終了」ボタンを表示。
  • 移動 → 次の地点で測定開始
    ユーザ操作「移動完了・測定開始」ボタンをタップ。
    自動スキャン実行 → 選択SSIDのBSSIDを抽出 → 接続試行（手順4へ）。
  • セッション終了
    ユーザ操作「セッション終了」ボタンをタップ。ラベルダイアログ表示（AP版と同様）。セッション全体のエントリのlabelをタイムスタンプ文字列に一括更新。
Android OS制約
接続試行ダイアログ（「〜に接続しますか？」）はAndroid OSが制御する。アプリは requestNetwork() を呼ぶのみで、ダイアログ表示・接続処理はOS任せ。このためステップ4の完全自動化は不可能。
4 選択SSIDが見つからない場合の処理

移動後のスキャンで、セッション開始時に選択したSSIDがスキャン結果に含まれない場合：

  1. 「選択したSSIDが見つかりませんでした（一覧）」ダイアログを表示
  2. スキャンエントリを保存（見つかったAPのみ記録、空の場合は access_points: []）
  3. そのまま移動待ち状態に移行。「移動完了・測定開始」「セッション終了」を表示
「見つからなかった」の表現方法（案A採用）
not_found_ssids フィールドは持たない。差分 で表現する：
targeted_ssids（対象SSID一覧）にあって access_points[].ssids に存在しないSSID ＝ そのエントリで見つからなかったSSID、とする。
5 送信JSONスキーマの変更点
追加フィールド

targeted_ssids フィールドをスキャンエントリのトップレベルに追加する。その他のフィールドはAP版と同一。

"scan_id": "uuid",
"device_id": "uuid",
"scanned_at": "2026-09-10T13:05:00",
"label": "session-uuid",  ← セッション終了後タイムスタンプに更新
"targeted_ssids": ["MyWifi", "CafeWifi"],  ← 新規追加
"location": { "latitude": 35.1, "longitude": 135.1, "accuracy_m": 5.0 },
"access_points": [
  {
    "bssid": "aa:bb:cc:dd:ee:01",
    "ssids": ["MyWifi"],
    "supplicant_final_state": "COMPLETED",
    ... （既存フィールド）
  }
  ← "CafeWifi" が見つからなかった場合はここに現れない（差分で把握）
]
targeted_ssids の役割
targeted_ssids − access_points[].ssids の和集合 ＝ そのエントリで見つからなかったSSID。分析時に「どの地点でどのSSIDが消えたか」を追跡できる。
