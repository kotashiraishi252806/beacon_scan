# 仕様: Supplicant測定のタイムアウトモード選択機能

## 指示（原文要約）

- 現行のタイムアウト（最初の状態遷移を3s以内で判定し、以降は状態遷移間の時間でタイムアウト）をモード1とする。
- モード2を追加する。モード2はユーザが入力したタイムアウト時間を、1つのAP（BSSID）の接続試行全体のタイムアウトとする。
- ユーザがタイムアウト時間を入力する。
- モード2ではユーザ入力タイムアウト時間いっぱいまで試行継続する。ただし、終了条件として妥当なものがあれば採用してよい。
- finalStateは、タイムアウト中に終了してよい条件を満たした時と、タイムアウトで終了した時で付与する（既存の付与方式を継承）。
- モードは測定者が任意に選択できる。

## 要件確定事項（本会話内で合意済み）

### モード2の早期終了条件（3条件のみ）

| 条件 | 検出点 | finalState |
|---|---|---|
| `ConnectivityManager.NetworkCallback.onAvailable` 発火 | NetworkCallback | `NETWORK_AVAILABLE` |
| supplicant状態 `COMPLETED` を受信 | `SUPPLICANT_STATE_CHANGED_ACTION` BroadcastReceiver | `AUTH_COMPLETED` |
| `connectivityManager.requestNetwork()` が例外 | 呼び出し直後の`runCatching` | `REQUEST_FAILED` |

### モード2で早期終了させないもの（モード1との差分）

- `idleHandler` による無変化タイマー（`FIRST_STATE_TIMEOUT_MS = 3_000L` / `NEXT_STATE_TIMEOUT_MS = 3_338L`）はモード2では作動させない。`IDLE_*` finalStateはモード2では発生しない。
- DISCONNECTED（ASSOCIATING以降に遷移した後に受信したDISCONNECTED）での早期終了を行わない。`PRE_TIMEOUT_<prevState>` finalStateはモード2では発生しない。
- `earlyExitOnAssociated` フラグ（ASSOCIATED受信での早期終了）はモード2では常に無効。`PRE_TIMEOUT_ASSOCIATED` finalStateはモード2では発生しない。

### モード2タイムアウト満了時のfinalState

- 既存命名を流用: `TIMEOUT_<mostAdvanced>` または `TIMEOUT_NULL`（遷移が1件も無い場合）。

### ユーザ入力タイムアウト値の仕様

- UI入力単位: 秒
- 最小: 1秒
- 最大: 60秒
- デフォルト: 30秒
- 空入力・数値以外の入力時: 測定開始ボタンを無効化して測定を開始させない。

### UI設計

- モード選択UI実装方式: `RadioGroup`（モード1/モード2の2択）+ `EditText`（タイムアウト秒数入力、モード2選択時のみ有効）。
- 配置場所: `activity_main.xml` の `switchAssociatedEarlyExit`（「ASSOCIATED到達時に即移行」トグル）の直下。
- モード2選択時、`switchAssociatedEarlyExit` は `isEnabled = false` にして無効化する。モード1選択時は現状どおり動作する。

### モード命名

- Kotlin enum: `MODE1_IDLE_RESET` / `MODE2_FIXED_TOTAL`
- UI表示名: 「モード1（状態遷移タイマー）」「モード2（固定タイムアウト）」

### モード情報の出力先

- 送信JSONへの新規フィールド追加は行わない。
- モード情報はラベル自動生成ロジック（`showAutoLabelDialog` 内の `autoLabel` 文字列）に組み込む。

### `measureAll()` 対応範囲

- `ConnectionMeasurementActivity.kt` の L641（`startMeasurementCycleAp` 内、セッション測定）と L845（通常スキャン直後の測定）の両方でモード選択を反映する。

## 内部実装の変更

### `SupplicantMeasurer.kt`

1. `enum class TimeoutMode { MODE1_IDLE_RESET, MODE2_FIXED_TOTAL }` を定義。
2. `measureAll()` のシグネチャに `timeoutMode: TimeoutMode = TimeoutMode.MODE1_IDLE_RESET` と `mode2TimeoutMs: Long = 30_000L` を追加。既存呼び出し側は呼び出し時に明示的に渡す。
3. `measureForAp()` 内でモード分岐:
   - MODE1: 現行コード（`idleHandler.postDelayed(idleTimeoutRunnable, FIRST_STATE_TIMEOUT_MS)`、BroadcastReceiver内の `idleHandler.removeCallbacks` → `postDelayed(idleTimeoutRunnable, NEXT_STATE_TIMEOUT_MS)`、`withTimeoutOrNull(DIALOG_TIMEOUT_MS)`）を維持。
   - MODE2:
     - `idleHandler` 関連の呼び出しをスキップ。
     - 外側待機を `withTimeoutOrNull(mode2TimeoutMs)` に置換。
     - BroadcastReceiver内のDISCONNECTED早期終了判定（L114-L121）をスキップ。
     - `earlyExitOnAssociated` フラグ判定（L108-L113）をスキップ。
     - COMPLETED判定（L104-L107）、`onAvailable`（L193-L199）、`requestNetwork` 例外（L223-L226）の3つのみ早期終了として機能する。
4. finalState算出ロジック（L239-L259）は現行のままで動作する（モード2では `idleExitOccurred` / `associatedEarlyExitOccurred` / DISCONNECTED経由の `brEarlyExitOccurred` が発生しないため、該当分岐は未使用となる）。

### `ConnectionMeasurementActivity.kt`

1. UI要素のバインディング追加:
   - `radioGroupTimeoutMode: RadioGroup`
   - `radioMode1: RadioButton`
   - `radioMode2: RadioButton`
   - `editMode2TimeoutSec: EditText`
2. モード選択変更時のリスナー:
   - モード1選択時: `editMode2TimeoutSec.isEnabled = false`、`switchAssociatedEarlyExit.isEnabled = true`
   - モード2選択時: `editMode2TimeoutSec.isEnabled = true`、`switchAssociatedEarlyExit.isEnabled = false`
3. 測定開始ボタン（`btnScan` / セッション測定開始ボタンなど）の有効/無効を入力値で制御:
   - モード1選択時: 入力値不問で有効化
   - モード2選択時: `editMode2TimeoutSec` の内容を `toIntOrNull()` で検証し、`null` または範囲外（1未満・60超）なら測定開始系ボタンを無効化
4. `measureAll()` 呼び出し時（L641, L845）に、選択中モードと入力タイムアウト値（秒→ミリ秒変換）を渡す。
5. モード1選択時の既存引数 `earlyExitOnAssociated = switchAssociatedEarlyExit.isChecked` を維持。モード2選択時はこの引数は内部で無効化される。
6. `showAutoLabelDialog` を変更し、`autoLabel` にモード情報を含める（下記AI補完）。

### `activity_main.xml`

- `switchAssociatedEarlyExit` の直下に以下を追加:
  - `RadioGroup`（水平方向）に `RadioButton` 2つ（`radioMode1`=「モード1（状態遷移タイマー）」、`radioMode2`=「モード2（固定タイムアウト）」）。初期チェックは `radioMode1`。
  - `EditText`（`inputType="number"`、初期値 "30"、ヒント「秒 (1-60)」、初期 `enabled=false`）。
- レイアウト制約は既存の `switchAssociatedEarlyExit` → 次要素（`activity_main.xml:104`, `117`）の `app:layout_constraintTop_toBottomOf` を新規UI要素の最下部に書き換える。

### `ScanData.kt`

- 変更なし（モード情報は `AccessPoint` にもJSONにも格納しないため）。

### `SupplicantMeasurer.kt` の定数

- `FIRST_STATE_TIMEOUT_MS`、`NEXT_STATE_TIMEOUT_MS`、`DIALOG_TIMEOUT_MS` は変更せずモード1で使用する。

## ラベル自動生成への組み込み【AI補完】

### 対象ロジック

`ConnectionMeasurementActivity.kt` の `showAutoLabelDialog`（L554-L583）内で以下のように `autoLabel` を生成している:

```kotlin
val autoLabel = "$startStr~$endStr"
```

### 変更案

`showAutoLabelDialog` に引数 `timeoutMode: TimeoutMode` と `mode2TimeoutMs: Long` を追加し、`autoLabel` を以下のように生成する:

- モード1の場合: `"$startStr~$endStr MODE1"`
- モード2の場合: `"$startStr~$endStr MODE2(${mode2TimeoutMs / 1000}s)"`

例:
- `"2026/11/18 10:30~11:45 MODE1"`
- `"2026/11/18 10:30~11:45 MODE2(30s)"`

### 呼び出し元（2箇所）での引数渡し

- L247: セッション測定終了時 → セッション測定開始時の選択モードと入力値を渡す
- L380: 自動スキャンスイッチOFF時 → 自動スキャン開始時の選択モードと入力値を渡す

### 単発スキャン（`startMeasurementCycleAp`経由ではない L845 側）のラベル

- 現状、単発スキャンのラベルは `""`（L811: `autoScanSessionId ?: ""`）で保存される。
- このパスは `showAutoLabelDialog` を通らないため、モード情報を付けるならラベル生成ロジックを新規追加する必要がある。
- 本仕様では単発スキャンのラベル付与は対象外とし、空文字のままとする。測定モードを区別したい場合はセッション測定または自動スキャンを用いることを前提とする。
- 承認時に単発スキャンもラベルにモード情報を付与する指定であれば、L811で空文字の代わりに `"MODE1"` / `"MODE2(${sec}s)"` を設定する案を追加する。

## 既存機能への影響

- モード1を選択し続ける限り、Supplicant測定本体の動作は完全に維持される。
- `supplicant_elapsed_ms`、`supplicant_states[].elapsed_ms`、`connection_started_at`、`supplicant_final_state` の基準点・意味・取りうる値（モード1経路）は不変。
- 送信JSONスキーマには変更なし。
- 既存スキャンデータの `label` フォーマットとは異なる文字列（"MODE1"等を含む）が今後保存されるが、サーバ側解析は文字列として受け取る前提のため影響しない見込み【AI補完・未確認】。

## 承認待ち項目

以下のAI補完箇所について、問題なければ承認してほしい。問題あれば差戻しまたは別指定。

1. モード1の`measureAll()` 呼び出し時、デフォルト引数 `TimeoutMode.MODE1_IDLE_RESET` と `mode2TimeoutMs = 30_000L` を設定する（既存呼び出しが変わらない構造）。
2. ラベルへのモード情報付与フォーマット:
   - モード1: `"$startStr~$endStr MODE1"`
   - モード2: `"$startStr~$endStr MODE2(${sec}s)"`
3. 単発スキャン（L845で `autoScanSessionId = null` のケース）のラベルは空文字のままにする。
4. モード2選択+入力範囲外のとき、`btnScan`、セッション測定開始系ボタン、自動スキャンスイッチの全てを無効化する（具体的な対象ボタンは実装段階で列挙）。
5. 入力値の記憶（SharedPreferencesへの永続化）は行わず、Activity再生成時はデフォルト30sに戻る方式とする。永続化が必要であれば指定してほしい。
