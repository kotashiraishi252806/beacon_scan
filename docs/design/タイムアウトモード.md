# 設計記録: Supplicant測定のタイムアウトモード選択機能

## 1. 目的

Supplicant測定のAP単位タイムアウト挙動を2モードから選択可能にする。
- モード1（MODE1_IDLE_RESET）: 現行方式。無変化タイマー（最初の状態まで3000ms、以降は状態受信ごとに3338msへリセット）＋全体10sキャップ。
- モード2（MODE2_FIXED_TOTAL）: ユーザが入力した秒数（1-60秒）を1APあたりのタイムアウトとする。無変化タイマーを使わず、入力時間いっぱいまで試行を継続する。

## 2. 入力

### UI入力
- モード選択: `RadioGroup`（`radioMode1` / `radioMode2`、初期は `radioMode1`）
- モード2タイムアウト値: `EditText`（`editMode2TimeoutSec`、秒単位、初期値30、`inputType="number"`、モード1選択時は `enabled=false`）

### 入力検証
- モード2選択時、`editMode2TimeoutSec` の内容を `toIntOrNull()` で検証し、`null` または `1..60` 範囲外なら測定開始時に Toast「モード2のタイムアウト値を1-60秒で入力してください」を出して開始を中止する。
- 検証対象の測定開始経路: `btnScan`、`btnMeasureSelected`、`btnNextLocation`。

### 内部状態
- セッション測定開始時に `sessionTimeoutMode` と `sessionMode2TimeoutMs` にUI値を捕獲する。
- 自動スキャン開始時に `autoScanTimeoutMode` と `autoScanMode2TimeoutMs` にUI値を捕獲する。
- `measureAll()` 呼び出し時にはUIの現在値を直接渡す（`currentTimeoutMode()` / `mode2TimeoutMs()`）。

## 3. 処理手順

1. ユーザが `radioMode1` / `radioMode2` を選択すると、`radioGroupTimeoutMode.setOnCheckedChangeListener` が発火し、`editMode2TimeoutSec.isEnabled` と `switchAssociatedEarlyExit.isEnabled` を切り替える（モード2選択時は `switchAssociatedEarlyExit` を無効化）。
2. 測定開始ボタンのクリックハンドラで `checkMode2InputBeforeMeasurement()` を呼び、モード2かつ入力無効ならToast表示して処理中断。
3. `measurer.measureAll()` 呼び出し時、`timeoutMode = currentTimeoutMode()`、`mode2TimeoutMs = mode2TimeoutMs()` を渡す。
4. `SupplicantMeasurer.measureAll()` 内で `this.timeoutMode` と `this.mode2TimeoutMs` を保持。`earlyExitOnAssociated` は `timeoutMode == MODE1_IDLE_RESET` のときのみ有効。
5. `measureForAp()` は `waitTimeoutMs` をモードで分岐（MODE1: `DIALOG_TIMEOUT_MS = 10000L`、MODE2: `mode2TimeoutMs`）し、`withTimeoutOrNull(waitTimeoutMs)` に渡す。
6. MODE1時のみ `idleHandler.postDelayed(idleTimeoutRunnable, FIRST_STATE_TIMEOUT_MS)` を呼び出す。MODE2では無変化タイマーを投入しない。
7. `supplicantReceiver.onReceive()` 内でモード分岐:
   - MODE1: 現行コードを維持（無変化タイマーリセット、COMPLETED/ASSOCIATED/DISCONNECTED早期終了）。
   - MODE2: `COMPLETED` 受信時のみ早期終了、他状態は記録のみで早期終了しない。
8. `finalState` 算出は既存ロジックを流用。MODE2では `idleExitOccurred` / `associatedEarlyExitOccurred` / DISCONNECTED経由の `brEarlyExitOccurred` が発生しないため該当分岐は未使用。
9. セッション終了（`btnEndSession` クリック）または自動スキャンOFF時、`showAutoLabelDialog(sid, startTime, timeoutMode, mode2TimeoutMs)` が呼ばれる。
10. `showAutoLabelDialog` 内で `autoLabel = "$startStr~$endStr $modeSuffix"` を生成。`modeSuffix` はMODE1なら `"MODE1"`、MODE2なら `"MODE2(${ms/1000}s)"`。

## 4. 出力

### 画面
- モード選択UIの表示とEditTextのenable/disable状態。

### ラベル
- 自動生成ラベル例:
  - モード1: `"2026/11/18 10:30~11:45 MODE1"`
  - モード2（30秒入力時）: `"2026/11/18 10:30~11:45 MODE2(30s)"`

### 送信JSON
- JSONスキーマには変更なし。モード情報は `label` フィールド経由でのみ送信される。

### Supplicant測定結果
- `supplicantFinalState` の取りうる値:
  - 全モード共通: `NETWORK_AVAILABLE`, `AUTH_COMPLETED`, `REQUEST_FAILED`, `SKIPPED`, `TIMEOUT_<mostAdvanced>`, `TIMEOUT_NULL`
  - モード1のみ発生: `PRE_TIMEOUT_<prevState>`, `PRE_TIMEOUT_ASSOCIATED`, `IDLE_<mostAdvanced>`, `IDLE_NULL`
  - モード2では上記 `PRE_TIMEOUT_*` と `IDLE_*` は発生しない。

## 5. 使用技術

- Kotlin `enum class TimeoutMode { MODE1_IDLE_RESET, MODE2_FIXED_TOTAL }`
- `kotlinx.coroutines.withTimeoutOrNull`
- `android.os.Handler` / `Looper.getMainLooper()`（MODE1の無変化タイマー保持）
- `android.net.wifi.SupplicantState`（COMPLETED/ASSOCIATED/DISCONNECTED等の判定）
- `android.net.ConnectivityManager.NetworkCallback`（`onAvailable` 検知）
- `android.widget.RadioGroup` / `RadioButton` / `EditText`（UI）
- `android.widget.Toast`（入力エラー通知）

## 7. 判断理由

### MODE2で無変化タイマーを無効化する理由
要件「入力タイムアウトいっぱいまで試行を継続する」に適合させるため、状態受信間隔での早期打ち切りを無効化した。

### MODE2で早期終了をCOMPLETED/NETWORK_AVAILABLE/REQUEST_FAILEDの3条件に限定する理由
これらは接続試行が原理的に継続不可能、または既に成功しているシグナルで、タイムアウトまで待ち続ける意味がないため。DISCONNECTED（進行後）は接続試行継続の可能性があり、ASSOCIATED は要件上は進捗の一過程に過ぎないため、MODE2では早期終了させない（ユーザ合意済み）。

### モード情報をJSONフィールドではなくlabelに入れる理由
ユーザから明示的に「送信JSONへのモード情報は付与せずに、label自動生成のロジックにタイムアウトモードを入力する案」の提案があり、これを採用。既存JSONスキーマを変更せずにモード区別を可能にする。

### `measureAll()` のデフォルト引数にMODE1を設定する理由
既存の呼び出し元（将来他のActivityから呼ばれる可能性）の互換性を保つため。

### 入力範囲1-60秒の理由
ユーザ指定（最小1秒、最大60秒、デフォルト30秒）。

### 入力検証を `TextWatcher` でボタン無効化ではなくクリック時Toastにした理由
`btnScan` の `isEnabled` は既存コードで複数箇所から変更されており（スキャン進行中・自動スキャン中・測定中等）、`TextWatcher` から上書きすると既存状態管理と競合する。クリック時検証＋Toastで同等のUX（測定開始を制限）を達成できる。
